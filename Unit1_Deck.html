Core

So — a coordinator is essential

Bring in Student 5 · CONTROL 👏

Control claps. On every clap, each unit does exactly one step, in order — Memory passes the data across, the processor adds, then increments, then Output shows 9. Correct, every time.

You now know: a coordinator is essential — it keeps every unit acting in the right order, at the right time.

That coordinator is the Control unit. We'll meet it properly — clocks, signals and all — right now, over the next two slides.

Core

That clap has a name: the clock cycle

① That clap has a real name — a clock pulse. Control sends one pulse to every unit.

② One pulse → one action. Every unit does exactly one step together, on the beat — then freezes and waits until the next pulse.

Our role-play, one clock cycle at a time

Clap 1 → read the numbers · Clap 2 → add · Clap 3 → increment · Clap 4 → display. Each clap was one clock cycle.

Clock cycle = the time from one pulse to the next — the steady beat the whole computer marches to.

Extended

What Control really runs on: the clock

① The Control unit generates a steady clock — a square-wave pulse, the computer's heartbeat — and sends it to every unit.

② On each tick, every unit does exactly one step in lock-step — latch a register, open a bus, set the ALU's operation.

③ Ticks per second = the clock rate (hertz). 3 GHz = 3,000,000,000 ticks/second → faster clock, faster machine — same architecture, better organisation.

Core

Control — the conductor: its two kinds of signal

The clock we just met is only half the story. Reading the instruction sitting in the IR and decoding it, the control unit drives every other unit at exactly the right instant by sending out two kinds of signal:

① Clock (timing) signals

The steady beat — WHEN each step may happen. Every unit acts on the tick, then waits.

② Control signals

WHAT to do on that tick — "latch this register", "put that value on the bus", "tell the ALU to add".

Processor = ALU + Control + registers. Its circuitry is spread through the machine, not sitting in one spot.

Clock (WHEN) + control signals (WHAT) — that completes the Control unit, the coordinator. Now let's watch all five units work together, then meet the other units one by one. →

The Memory Unit

Feeding the ALU: registers & main memory

Core

The working tier: main memory (RAM) — out on the board

What it is

Semiconductor DRAM on the motherboard, reached over the system bus. It holds the entire running program and its data. Random-access — any address takes the same fixed time. Volatile: it empties when power is cut.

Why it feels slower

It is off-chip and far larger, so every access travels the bus and costs many cycles. When the cache misses, the processor must wait for this trip — the reason caches exist at all.

Core

The permanent tier: secondary storage — big, cheap, slow

What it is

SSD, hard disk, flash. Non-volatile — keeps data with the power off. Cheap per GB and enormous. Your programs and files live here until you run or open them.

Why it's so slow: not truly random-access

A hard disk must physically seek and wait for the platter to spin; even an SSD works in blocks, not single words. So the CPU can't use it directly — data is first copied into RAM. Access is ~100,000× slower than main memory.

The five functional units — the definition to reproduce.

A computer has five functionally independent main parts:

  • Input — accepts coded information from outside.
  • Memory — stores programs and data.

Basic Operational Concepts

The five boxes are wired together. But nothing has run yet — so what actually makes the machine move?

Supporting

Unit 1 · Ch 1

Now · Ch 2

Everything new here rests on something you already own. Keep the adder and the five units in mind.

?
Think about it
A program is just numbers sitting in memory. How does a lifeless list of numbers ever start executing — and get its life?
Let's build the answer step by step: first see exactly how the program sits in memory, then find out who chooses which instruction runs next.
Core

The stored-program idea

The whole program is stored in memory, each instruction at its own address (100, 104, 108 …). The processor fetches them one at a time — but with so many instructions, which one does it take next, and who decides?

Symbolic assembly language for a processor with general-purpose registers — the load/store convention used in the textbook (Hamacher): only Load and Store touch memory; arithmetic is register-to-register. Same C = A + B program throughout the module.

Core

Who picks the next instruction? The Program Counter

Out of all those instructions, one special register decides — the Program Counter (PC). It always holds the address of the next instruction to fetch.

The processor reads whatever the PC points to, runs it, then the PC advances to the next address — so the lifeless list finally runs itself, in order.

Core

The PC isn't alone — the special-purpose registers that run the show

🧠
Get this into your memory
Write these four one-liners in the exam — 4 marks, guaranteed.
  • Program Counter (PC) — holds the memory address of the next instruction to be fetched.
  • Instruction Register (IR) — holds the instruction currently being executed.
  • Memory Address Register (MAR) — holds the address of the memory location to be accessed.
  • Memory Data Register (MDR) — holds the data being written to, or just read from, memory.
Supporting

First, a shorthand for what instructions do: RTN

RTN stands for Register Transfer Notation — a symbolic way to write what an instruction moves between registers and memory.

R2 ← [A]

[ A ] means "the contents of address A". The ← means "is copied into".

Example — suppose location A holds the value 5. Then Load R2, A (R2 ← [A]) copies 5 into R2: afterwards R2 = 5, and A itself still holds 5.

Rule: the source is unchanged; the destination is overwritten.

Get this into your memory
The instruction cycle — the classic 5-mark answer.

Every instruction runs in two phases:

  • Phase 1 — Fetch & Decode — PC → MAR → memory; the instruction is read into MDR, then into IR; the control unit then decodes the IR to work out the operation.
  • Phase 2 — Execute — the operand's address is sent to MAR, the operand is read into MDR, the ALU acts, and the result is stored. Finally the PC is incremented to point at the next instruction.

Fetch and decode together make up the first phase — so what some books split into three steps (fetch · decode · execute) is really two phases: get-and-understand, then do.

RTN: R2 ← [A] — contents of A copied into R2; source unchanged.

The PC points, the IR holds, the ALU acts.
A lifeless list of numbers becomes a living process — one fetch–decode–execute at a time.

Bus Structures

Five units must swap data constantly. Do we run a private wire between every pair — or one shared highway they take turns on?

Core

A bus is a shared set of wires

Core

Single-bus organisation

All units connect to one common bus. It is the sole path for every transfer.

✔ Advantages

Low cost · simple to design · easy to add a new device — just tap the bus.

✘ Disadvantage

Only one transfer at a time — the bus becomes the bottleneck.

Supporting

Two buses — instructions and data move at the same time

Two-bus (dual) organisation

One bus carries instructions, a second carries data, so a fetch and a data move can happen together — easing the single-bus bottleneck at the cost of extra wiring.

Supporting

Multiple buses — each matched to its speed

What is the system bus?

The system bus is the machine's main highway — it ties the processor (through its cache) to main memory and, via a bridge, to everything else. It bundles address + data + control lines together.

Why several buses?

Each bus runs at the speed of what it joins: a very fast processor–cache bus, the system bus to memory, and a slower expansion bus for peripherals. More parallelism, more wiring.

Core

Every bus is really three groups of lines

Address bus

Where? Carries the address to access; k lines → 2k locations. Usually one-way (processor → memory).

Data bus

What? Carries the data / instruction word — both ways.

Control bus

When / which way? Read/Write, timing and status signals.

🧠
Get this into your memory
Bus definition + the three line-groups — a reliable 5-marker.

Bus — a shared set of wires that transfers data and control information between the functional units; only one source may drive it at a time (built with multiplexers or tri-state buffers).

  • Address bus — carries the address (k lines → 2k locations).
  • Data bus — carries the data/instruction word.
  • Control bus — carries Read/Write, timing and status signals.

Single = one shared path (cheap, one-at-a-time); multiple = parallel paths (faster, costlier).

🔑
One highway, taken in turns.
A bus trades simultaneous traffic for simplicity — and address, data and control lines make every transfer say where, what, and when.

Memory Locations & Addresses

Memory is millions of numbered lockers. Before we can store anything, we must agree on the size of a locker and how we number them.

Core

Three quantities of information

Bit

A single 0 or 1 — the smallest unit.

Byte

A group of 8 bits. Holds one character.

Word

The group the processor handles in one go — its word length, typically 16 / 32 / 64 bits.

A 32-bit word = 4 bytes = one signed integer, or four ASCII characters.

Core

What is a word? 32-bit vs 64-bit

?
Address arithmetic
If a machine uses a 24-bit address, how many locations can it name? What about 32 bits?
k address bits → 2k locations. 224 = 16M; 232 = 4G. Every extra address line doubles the reachable memory.
Core

Byte-addressable memory

Core

Big-endian vs little-endian

?
Alignment
For a 32-bit machine, is a word starting at address 6 "aligned"? What about address 8?
Aligned = starts at a multiple of the word size (4). So 8 is aligned; 6 is not. Unaligned access still works but is slower.
🧠
Get this into your memory
Addressing facts examiners love.
  • Bit / Byte / Word — a bit is 0/1; a byte is 8 bits; a word is the n-bit unit the processor handles at once (word length 16/32/64).
  • Byte-addressable — every 8-bit byte has a distinct address (0,1,2,…).
  • k-bit address → 2k addressable locations.
  • Big-endian — most-significant byte at the lowest address; Little-endian — least-significant byte at the lowest address.
  • Aligned word — begins at an address that is a multiple of the word size in bytes.
🔑
Number every byte; group them into words.
Fix the word size, the byte order and the alignment — and any value in memory has one exact address.

Memory Operations & Instructions

There are really only two things you can do to memory — read it and write it. From those two verbs, every program is built.

Core

Read — copy from memory, over the three buses

Read = address (where) + Read (control); memory answers with a copy on the data bus. RTN: DR ← [LOC].

Core

Write — copy to memory, over the three buses

Write = address + data + Write; the old value is gone for good. RTN: M[LOC] ← R1.

🧠
Get this into your memory
The two memory operations, in exam words.
  • Read — the processor sends an address; memory returns a copy of the contents. Source is unchanged.  DR ← [LOC]
  • Write — the processor sends an address and data; memory stores it, overwriting the old value.  M[LOC] ← R1
Supporting
Memory operations done — now: instructions

Two languages for one action

RTN — to describe

R2 ← [A]
Symbolic; [ ] = contents, ← = copied into. For explaining hardware.

Assembly — to program

Load R2, A
Mnemonics a human writes; the assembler turns it into the binary object program.

We can read and write memory, and we can describe it two ways. So now the real question: what exactly is an instruction made of?

Core

Every instruction = opcode + operand(s)

Keep the opcode fixed, and we can classify any instruction three ways — by what it does, by how many operands, and by where the operand lives. One lens per slide next.

Core
LENS ① · WHAT IT DOES

By functionality — grouping instructions by the job they perform

Same five families you'd find on any CPU — only the exact mnemonics change from chip to chip.

Core

By number of operands — the same job C = A + B, written four ways

Fewer addresses → shorter instructions, but you need more of them. The address count is the instruction format; general-register / accumulator / stack is the CPU organisation — two ideas that travel together.

Core
LENS ③ · WHERE THE OPERAND LIVES

By format — three basic instruction formats

FormatWhere the operand is Examples (generic)Textbook (Morris Mano)

Input–Output an I/O device — no memory address In · Out INP · OUT · SKI · ION

Why two different sets of names? Assembly language is machine-specific — the same idea is Load in our textbook, LDA in the Morris Mano textbook, MOV on x86, LDR on ARM. We teach with a generic mnemonic so the concept is clear; for a real chip you open its manual and translate.

Core

Two design philosophies: RISC vs CISC

RISC — Reduced Instruction Set

A small, simple set of instructions, each optimised to run in about one clock cycle.

CISC — Complex Instruction Set

A large, rich set; single instructions do complex, multi-cycle work and may touch memory directly.

The trade-off in one line: CISC does more per instruction; RISC does less per instruction but runs them faster and more predictably. Next: you decide which one you'd build.

Classify it
In a RISC machine, which of these is illegal?  Add R1,R2,R3  ·  Add R1, LOC
The second. RISC forbids arithmetic on a memory operand — you must Load LOC into a register first, then Add. That's the whole "load/store architecture" in one rule.
🧠
Get this into your memory
Instructions, formats & RISC vs CISC — high-frequency exam answers.
  • Instruction = opcode (the operation) + operand(s) / address (what it acts on).
  • Assembler — translates symbolic assembly (mnemonics) into the binary object program.
  • Instruction formats — memory-reference, register-reference, and input–output.
  • RISC — one-word instructions; load/store architecture (only Load/Store access memory); simple, pipeline-friendly.
  • CISC — variable-length, multi-word instructions; arithmetic may act directly on memory operands.

Addressing Modes

Every instruction has to say where its operand is — a constant, a register, an address, or a pointer. How many ways can one instruction reach its data?

Core

Same operation — but where is the operand?

Ask a friend to fetch something. Four honest answers:

“Here — take it”

The value sits inside the instruction.
Immediate

“It’s in your pocket”

The value is in a register.
Register

“In locker 1000”

The instruction gives the memory address.
Absolute / Direct

“Read the note in locker 1000”

That address points to another address.
Indirect

How an instruction names where its operand lives is its addressing mode.

?
Think back to Chapter 5
Can an Add take its operand straight from memory?
CISC: yes — Add B, A operates on memory directly.   RISC: no — arithmetic uses registers/immediates; only Load / Store touch memory. So in RISC these memory-addressing modes ride on Load / Store; in CISC, on almost any instruction.
Core

Immediate — the value is inside the instruction

Written Move R2, #5 → R2 ← 5 — destination first, exactly like Load and Add. The # marks an immediate operand that travels with the instruction — perfect for setting a register to a constant.

Core

Register — the operand is in a register

Add R4, R2, R3  →  every operand names a register.

The effective address is the register — no memory access, so it is the fastest way to supply an operand. This is the everyday mode of the RISC machine from Chapter 5.

Why keep operands in registers?

A register read is a tiny fraction of a memory read. RISC holds operands in registers precisely so an instruction can finish in about one clock cycle.

Core

Absolute (Direct) — the instruction holds the address

Load R2, A → R2 ← [A]. One memory access. This is the exact mode our C = A + B program used to reach A, B and C.

Core

Indirect — the address of the address (a pointer)

Load R2, (R5)  →  R2 ← [[R5]] — now follow the pointer, step by step:

Two memory accesses in all. This is the key to pointers, arrays-of-pointers and linked structures.

Core

Index — a base register plus an offset

Load R2, 20(R5)  →  EA = 20 + [R5]

Made for arrays

Fix the base R5 at the array's start; change the offset 20 to step to any element. If R5 = 1000, then 20(R5) reaches address 1020.

Richer cousins: base-with-index (Ri, Rj) → EA = [Ri] + [Rj], and base + index + offset X(Ri, Rj) — for records and 2-D data.

Core

Relative — index mode, but the register is the PC

EA = X + [PC]

Branch>0 LOOP doesn't store LOOP's full address — it stores the offset X from the current PC. The target is computed as PC + X.

Hold onto this

Relative addressing is exactly how a program jumps to another instruction — which is the whole question of the next chapter.

Core

Autoincrement / Autodecrement — walk through data

Autoincrement  (R5)+

Use [R5] as the address, then R5 ← R5 + 1.
Step forward through an array, element by element.

Autodecrement  −(R5)

R5 ← R5 − 1 first, then use [R5].
Natural for a stack — push and pop.

The register updates itself, so a loop needs no extra "advance the pointer" instruction each pass.

Instruction Sequencing

You just built PC-relative addressing — a target computed as PC + offset. That is exactly how a program jumps. So what decides which instruction runs next? Master that, and a computer can loop, choose, and decide.

Core

Straight-line: just keep adding to the PC

Each fetch auto-increments the PC by the word length, so instructions run in address order. This is called straight-line sequencing.

And that is one of only two kinds of instruction sequencing: straight-line (the PC just steps on) and branching (a new address is loaded into the PC) — next.

Core

Unconditional branch — a jump: load a new address into the PC, always

An unconditional branch (a jump) puts a fixed target address into the PC every time — used to loop back to the top of a block, or to skip ahead.

But on its own this loops forever. To decide whether to jump, the machine must check something first — and that is a conditional branch → next.

Core

Conditional branch — check first, then decide: put the larger of A and B into MAX

How does it know? The Compare R1, B subtracts, then stores the outcome in the processor's condition-code flags — a small status register that records was the result zero? negative? … The Branch>0 that follows simply reads those flags. That is why a conditional branch always sits right after an instruction that sets them.

Then, exactly like the jump, it loads the new address into the PC (taken) — or it does not, and the PC just steps on (not taken). One checked choice — that is all a conditional branch is.

?
Target & offset
Our Branch>0 116 sits at address 108. Instead of storing the target "116", many machines store the offset +4 (counted from the next instruction, 112). Why is that smarter?
The offset is small and position-independent — the same code runs wherever it's loaded in memory. Effective address = PC + offset (PC already points to the next instruction). Target = where you land; offset = the distance.
🧠
Get this into your memory
Sequencing — the exam essentials.
  • Straight-line sequencing — the PC is auto-incremented after each fetch, so instructions execute in increasing address order.
  • Branching — a branch loads a new address into the PC instead of PC+4. Two kinds: unconditional and conditional.
  • Unconditional branch (jump) — always taken; PC ← target every time (e.g. loop back).
  • Conditional branch — taken only if a tested condition is true. The preceding Compare/arithmetic stores its result in the condition-code flags, which the branch reads (e.g. Branch>0).
  • Branch target = the destination address; offset = target − (PC of next instruction).
🔑
The PC is the story-teller.
Increment it and the program marches; overwrite it and the program loops, chooses, decides. All of control flow is just editing one register.
