Measuring pipeline performance
We keep saying "speedup approaches k." Time to put real numbers on it — and to account, honestly, for every stall that pulls us below the ideal.

The basic performance equation

Put numbers on it · Execution time depends on how many instructions run, how many cycles each takes on average, and how fast the clock ticks.
T = ( N × S ) / R N = instructions · S = avg cycles per instruction · R = clock rate
Throughput Pnp = R / S   →   pipelined ideal (S=1): Pp = R Non-pipelined S = 5; ideal pipeline drops S to 1 → up to 5× the throughput.

Reality: stalls push S above 1

Honest accounting · The ideal is S = 1. Every kind of stall we met adds a penalty term — and these terms simply add up.
S = 1 + δstall + δbranch + δmiss
  • δstall — load-use dependencies. e.g. 25% loads × 40% followed by a dependent × 1 = 0.10
  • δbranch — branch mispredictions. e.g. 20% branches × 10% mispredict × 1 = 0.02
  • δmiss — cache misses (often the biggest). e.g. (0.05 + 0.30×0.10) × 10 = 0.8
🎤 Worked example
Example 6.2 · 20% of instructions are branches, static "not-taken" prediction, 1-cycle penalty. Compare 30% vs 70% of branches actually taken.
  • δbranch = 0.20 × 0.30 × 1 = 0.06 → S = 1.06   (30% taken)
  • δbranch = 0.20 × 0.70 × 1 = 0.14 → S = 1.14   (70% taken)
Speedup of the better case = (1.14 / 1.06 − 1) × 100 ≈ 7.5% faster. The more branches are taken, the more a not-taken guess costs.

So how deep should the pipeline be?

Diminishing returns · n stages promise up to n× throughput — but the penalties we just added scale against depth.
  • Deeper → shorter clock period → higher clock rate.
  • But more instructions in flight → more dependencies, bigger branch penalty → larger δ terms.
  • The clock is ultimately limited by the slowest basic operation (usually the ALU).
  • Sweet spot in practice: ~10–20 stages at several GHz.
🔑
Real speedup = the ideal, minus every stall.
And the cache-miss term is often the one that dominates.

Beyond one per cycle: superscalar
A single pipeline can finish, at best, one instruction every cycle. To go faster still, we stop waiting in one line — and open several checkouts at once.

Multiple issue — more than one per cycle

Break the ceiling · A single pipeline tops out at one instruction per cycle. A superscalar processor equips itself with several execution units and issues multiple instructions each cycle.
  • Fetch and decode two or more instructions every cycle into an instruction queue.
  • A dispatch unit sends independent instructions to different execution units.
  • Throughput can exceed one instruction per cycle — this is multiple-issue.

Keeping many-in-flight correct

The price · With several units running at once, instructions may finish out of order. Extra hardware keeps the results correct and exceptions precise.
  • Reservation stations hold a dispatched instruction until all its operands arrive.
  • Out-of-order execution: independent instructions run as soon as they're ready.
  • Register renaming uses temporary registers to avoid false conflicts.
  • A reorder buffer commits results in program order → precise exceptions.
