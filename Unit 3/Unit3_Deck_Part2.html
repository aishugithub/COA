🎤 Ask the class
Think · Look at when the answer actually exists, not when it gets written.
The Add's ALU finishes computing R2 by the end of cycle 3.
The Subtract needs R2 in its Compute stage, cycle 4.
So must we really stall?
No. The value is sitting at the ALU output after cycle 3 — just route it straight across to the Subtract, without waiting for the register write.

Operand forwarding — no stall at all

The idea · Take the Add's result the moment the ALU produces it (end of cycle 3) and feed it directly into the Subtract's ALU input in cycle 4. Zero stall cycles.

The hardware that makes it possible

Under the hood · The ALU result is captured in register RZ. Add wires from RZ back to the ALU inputs, plus multiplexers to choose them — that is all forwarding needs.

When forwarding isn't enough: the Load
Forwarding erased the stall for an Add. But what if the value comes from memory instead of the ALU — can we still hand it over in time?

A load's value arrives one stage later

The catch · A Load reads its data in the Memory stage — a whole stage after the ALU. Forwarding still helps, but it can't beat time: one stall cycle is unavoidable.

🎤 Ask the class
Predict · Compare where each value is born.
Add-then-use costs no stall, but Load-then-use costs one. Why?
The ALU result exists after the Compute stage; the memory value only after the Memory stage — one stage later, so it reaches the next instruction one cycle too late to fully forward.
🔑
Forwarding removes most data-hazard stalls —
but a load-use pair always costs at least one cycle.
CHAPTER 3

Software help & seeing it live
Hardware isn't the only fixer. The compiler can rearrange code to dodge hazards — and a simulator lets us watch every stall and forward happen in real time.

Letting the compiler handle it

Another route · If the hardware won't forward, the compiler must create the delay itself — by inserting NOPs, or better, by reordering useful work into the gap.
  • Insert NOPs: place three do-nothing instructions between the dependent pair — simple, but pure waste.
    Add     R2,R3,#100    NOP · NOP · NOP    Subtract R9,R2,#30
  • Reorder instead: move independent instructions into those slots so the CPU does real work while the value settles — no wasted cycles.
  • This is instruction scheduling — the compiler and the pipeline designed hand-in-hand.
