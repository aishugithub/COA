1 Microoperations

Ways this is asked → “Define a microoperation”, “Microoperation vs instruction”, “Give an example of a microoperation with RTL”.
What is a microoperation? Give one example with its RTL. 3–5 marks

A microoperation is an elementary operation performed on the data stored in registers, carried out in one clock pulse (one clock cycle). Typical microoperations are load, clear, count, shift, add on register contents.

Example with RTL: R1 ← R1 + R2 — in one clock, the adder adds the contents of R1 and R2 and latches the sum back into R1. Another: R2 ← R1 (a transfer microoperation).

Key contrast (often the second half of the question): one instruction is what the programmer writes (opcode + operands, e.g. ADD R1, R2); the CPU carries it out as a sequence of microoperations. So one instruction = a sequence of microoperations.

For example, ADD R1, R2 unfolds into: MAR ← PC; MDR ← M[MAR], PC ← PC+1; IR ← MDR; R1 ← R1 + R2 — four microoperations across four clocks.

2 Register Transfer Notation (RTN / RTL)

Ways this is asked → “Explain register transfer notation”, “What do [ ], ← and the comma mean?”, “Write the RTL for …”.
Explain Register Transfer Notation with the meaning of each symbol. 3–5 marks

Register Transfer Notation (RTN), also called Register Transfer Language (RTL), is a symbolic notation used to describe the movement of information between registers and memory. It uses just four elements:

SymbolMeaningExample
Letters (and numbers)the name of a registerMAR, R2, PC
Parentheses ( )a part / field of a registerR2(0–7), R2(L)
Arrow ←transfer; the source is unchanged, the destination is overwrittenR2 ← R1
Comma ,two (or more) transfers in the same clock pulseR2 ← R1, R4 ← R3
Also worth a line: square brackets denote contents of — R2 ← [A] means “the contents of location A are copied into R2”. The source keeps its value; only the destination changes.

3 Register Transfer Happens Only on a Control Signal

Ways this is asked → “What is a control function?”, “Explain P : R2 ← R1”, “Why doesn’t a register transfer happen on its own?”.
How is a register transfer made to happen at the right time? Explain the control function P : R2 ← R1. 3–5 marks

RTL says what moves, but never when. A real register transfer must wait for a control signal that says “now”. This is written as a control function:

P : R2 ← R1

meaning the transfer R2 ← R1 occurs only when the control signal P = 1 (at the clock edge).

  • The two registers are permanently joined by n parallel wires (n = word width, e.g. 32 lines in a 32-bit CPU), so R1’s value is always present on the wires.
  • If P = 0, R2’s load line stays shut — the value is on the wires but nothing is latched, so nothing moves.
  • If P = 1, R2 latches R1’s value on the clock edge.

In one line: control turns a permanent wire connection into a timed transfer.

4 Register Transfer on Hardware — the Common Bus

Ways this is asked → “How is a common bus built?”, “What are the two ways to build a bus?”.
How is a common bus built so any register can transfer over it? 2–3 marks

A common bus is one shared path that any register can send to (instead of a private wire between every pair). Only one source may drive it at a time. It can be built in two ways:

  • Multiplexers — the select lines choose which register reaches the bus. (For k registers of n bits: n multiplexers, each k×1.)
  • Tri-state (three-state) buffers — each register drives the bus through a buffer; a decoder enables exactly one, while all the others sit in the high-impedance state (electrically absent).
Answer in one line: a common bus is built either from multiplexers or from tri-state buffers with a decoder — either way, one source drives the bus at a time. (No further circuit detail is needed for the exam.)

5 Memory Transfers — Read & Write (in full)

Ways this is asked → “Explain memory Read and Write operations in detail”, “What travels on the address/data/control bus during Read/Write?”, “Write the RTL and the control signals for a memory Read and a Write”.
Explain a memory READ and a memory WRITE in full — the RTL, the control signals fired, and what travels on the address, data and control buses. 10 marks

The processor reaches memory through two registers: the MAR (Memory Address Register) holds the address, and the MDR (Memory Data Register) holds the data. All data to and from memory passes through the MDR — a register such as R1 never reaches memory directly. (In Morris Mano these are named AR and DR.)

The processor and memory are joined by the three buses from Unit 1 — but here we say exactly what each carries, what the control unit fires, and the RTL for each beat.

MAR drives the address bus; MDR sits on the data bus; the control unit drives the Read/Write line.

① MEMORY READ — fetch a word (e.g. bring the value of location A into the CPU):

BeatControl signals firedRTLWhat travels
1PCout, MARin (latch the address into MAR)MAR ← [PC]Address bus carries the address (MAR → memory, one-way)
2Read = 1 on the control busReadControl bus tells memory this is a read
3MDRin (latch the returned word)MDR ← M[MAR]Data bus carries the word (memory → MDR)

The addressed word is copied to the CPU; memory is left unchanged. In one line of RTL: MAR ← [PC]; Read; MDR ← M[MAR].

② MEMORY WRITE — store a word (e.g. write R1 to location A):

BeatControl signals firedRTLWhat travels
1MARin (address into MAR)MAR ← AAddress bus carries the address (MAR → memory)
2R1out, MDRin (data into MDR)MDR ← [R1]internal — data moves R1 → MDR
3Write = 1 on the control busWrite; M[MAR] ← [MDR]Data bus carries the word (MDR → memory); control bus asserts Write

Memory overwrites the addressed word. In RTL: MAR ← A; MDR ← [R1]; Write; M[MAR] ← [MDR].

The three things an examiner checks: (1) the address bus is one-way and is always driven by MAR; (2) the data bus is bidirectional and always passes through MDR — its direction (in on Read, out on Write) is decided by the control bus; (3) the control unit fires MARin → Read/Write → MDRin in that order. Everything to and from memory passes through MDR.

One-liner: Read = MDR ← M[MAR]; Write = M[MAR] ← MDR — address on the address bus, data on the data bus, Read/Write on the control bus.

6 Operations of the ALU

Ways this is asked → “Explain the arithmetic/logic/shift microoperations”, “How does one adder do add/subtract/increment/decrement?”, “How is subtraction done?”, “Explain the shift microoperations”.
Give an overview of the ALU (the Arithmetic–Logic–Shift Unit). 3–5 marks

The ALU is one unit that folds together three circuits — arithmetic, logic and shift. Both operands A and B feed all three in parallel; a final multiplexer passes just one result, chosen by select lines.

BlockDoesChosen by
Arithmetic circuitadd / subtract / increment / decrementS1 S0 and Cin
Logic circuitAND / OR / XOR / NOTS1 S0
Shiftershift left / shift rightshift control
Final 4→1 MUXpicks which block’s result comes outS3 S2 (00 arith · 01 logic · 10 shr · 11 shl)
One-liner: full ALU select = S3 S2 S1 S0 + Cin — S3 S2 pick the block, S1 S0 + Cin pick the operation inside it. Multiply and divide are not separate boxes — they are add/shift sequences.
How does a single adder perform add, subtract, increment and decrement? (the one-adder + MUX arithmetic circuit) 5 marks

Put a MUX on the second input Y of one n-bit adder and let the control unit choose the word fed in, together with the carry-in Cin. The same adder then does four operations (worked for A = 0101 = 5):

OperationSelect S1 S0Y (MUX output)CinAdder computesResult
ADD (A+B)00B = 00110A + B1000 = 8
SUB (A−B)01B̄ = 11001A + B̄ + 10010 = 2
INC (A+1)100…0 = 00001A + 0 + 10110 = 6
DEC (A−1)111…1 = 11110A + (−1)0100 = 4
Read the table this way: the control unit’s select lines choose what enters Y (B, its complement B̄, all-0s, or all-1s) and set Cin. One adder + one MUX = four operations. The carry-out is dropped.
How is subtraction done without a subtractor? (method of complements / adder–subtractor) 3–5 marks

Subtraction is turned into addition using the method of complements: A − B = A + (2’s complement of B), and the 2’s complement is “flip every bit, then add 1”.

Worked: 5 − 3. B = 0011 → flip → 1100 → +1 → 1101. Now add: 0101 + 1101 = 1 0010; drop the carried 1 → 0010 = 2. ✓ same answer, using only addition.

In hardware this is one circuit — an adder–subtractor — controlled by a mode line M:

MB into adderCinAdder computesOperation
0B (unchanged)0A + BADD
1B̄ (flipped, via XOR)1A + B̄ + 1 = A − BSUBTRACT

The one mode line M feeds every B-XOR and the carry-in — so Cin = 1 is exactly the “+1” that completes the 2’s complement. Flipping is one XOR per bit (a controlled NOT).

Explain the logic (bitwise) microoperations — how OR sets a bit and AND clears a bit — with an example, and why they matter. 5 marks

A logic microoperation applies a Boolean op to each bit position on its own. A second word we choose — a mask — decides which bits to touch. The two everyday jobs are:

  • OR sets a bit — where the mask has a 1, that bit is forced to 1; where the mask is 0, the bit is left alone.
  • AND clears a bit — where the mask has a 0, that bit is cleared; where the mask is 1, the bit passes through unchanged.
JobWorked example (8-bit)Effect
AND — clear / mask1011 0110 AND 0000 1111 = 0000 0110high nibble cleared to 0; low nibble kept
OR — set1011 0000 OR 0000 1111 = 1011 1111low nibble forced to 1; high nibble left alone
Why they matter (keep it brief): these bit ops let you set, clear or test individual flags / control bits — status-register flags, permission bits, or an IoT GPIO pin driven high or low — without disturbing the neighbouring bits. Each is a single, cheap ALU clock pulse. (Extract/insert of a field is the same masking idea and can be skipped for the exam.)
Explain the shift microoperations — logical left, logical right, arithmetic right and circular — with one example each. 5 marks

A shift = ① move every bit one place, then ② fill the vacated end. The four types differ only in what fills that end:

ShiftWhat fills the vacated endExample (one place)Meaning
Logical left (shl)a fresh 0 enters at the right0110 → 1100  (6 → 12)× 2
Logical right (shr)a fresh 0 enters at the left0110 → 0011  (6 → 3)÷ 2 (unsigned)
Arithmetic right (ashr)the sign bit is copied back in1110 1100 → 1111 0110  (−20 → −10)signed ÷ 2
Circular (rotate)the bit that falls off wraps to the other end1001 →(right) 1100no bit lost
The one-liner examiners want: left shift ≈ ×2, right shift ≈ ÷2 — shifting by k means ×2k or ÷2k. A shift is just rewiring in one clock, far cheaper than a full multiply. Arithmetic right is special because it copies the sign bit, so a negative number still halves correctly. (How a general multiply is actually done is not needed for this exam.)

7 Bus Organisation of the Processor

Ways this is asked → “Single-bus vs multiple-bus (three-bus) organisation”, “How many clocks does an ALU op take on each?”, “Advantages / trade-off”.
Explain the single-bus and the three-bus (multiple-bus) organisation of the processor, and how each affects the number of clocks. 5–10 marks

This is the bus inside the processor (Unit 1’s bus was between the CPU, memory and I/O; here we open the CPU lid and look at the internal lanes joining the registers and the ALU).

Single-bus organisation. Everything inside the processor — the registers, the ALU, MAR and MDR — hangs off one shared internal bus. Only one value can be on the bus per clock. So adding two numbers means shuttling the operands across the bus one at a time, and an ALU operation spreads over several clocks. Main memory is outside; the CPU reaches it only through MAR (address) and MDR (data).

Single-bus: cheap and simple, but one transfer per clock (the bottleneck).

Three-bus (multiple-bus) organisation. Two source buses (Bus A and Bus B) carry both operands to the ALU at once, and Bus C returns the result to the register file — so a register-to-register operation finishes in one step.

Three-bus: Bus A + Bus B feed the ALU together, Bus C returns the result — one step.
The exam contrast: Add R4, R2, R3 takes several clocks on a single bus (move R2, then R3, then the result), but one clock on a three-bus datapath (R2 on Bus A, R3 on Bus B, result on Bus C). More buses → fewer clocks per instruction, at the cost of more wiring.

8 Execution of a Complete Instruction

Ways this is asked → “Draw the datapath”, “Explain the five phases”, “Trace C = A + B beat by beat with RTL”, “How is the effective address computed?”.
Draw the processor datapath and explain the five phases (beats) an instruction goes through. 5–10 marks

The datapath is the fixed lane of registers and wires that data travels along. It uses interstage registers — RA, RB (the two operands), RZ (the ALU result), RY (the value to write back) and RM (data to/from memory) — each just parks a value between one step and the next.

Datapath: register file → RA/RB → ALU → RZ → RY → back to the register file; RM branches off for memory.

Every instruction rides the same five beats, one per clock:

BeatPhaseWhat happens
1Fetchread the instruction at [PC]; increment the PC
2Decodework out the operation; read the source registers
3ComputeALU performs the operation, or computes an address
4Memoryread/write data — only for Load / Store
5Write-backresult returns to the destination register
Trace the program C = A + B one beat at a time, showing the RTL in each of the five phases. 10 marks

The program is four instructions; each walks all five phases before the next one’s Fetch begins (no overlap). Fetch always runs the same MAR→MDR→IR chain. Only the indexed load and the Add give the ALU real work in Compute — the two absolute ops have nothing to compute.

How is the effective address computed? 3–5 marks

The effective address (EA) is the actual memory address the instruction finally uses. For an indexed / based operand it is built by the ALU in the Compute beat:

effective address = [base register] + offset

Worked: Load R5, 20(R7) with R7 = 1000. Step 2 (Decode) reads the base RA ← [R7]; Step 3 (Compute) adds the offset RZ ← [R7] + 20 = 1020; Steps 4–5 read M[1020] through MDR and write it into R5.

Key line: the ALU that does arithmetic is the same adder that builds the address. Absolute addressing is just the special case where the full address is already in the instruction, so no base register is added and the Compute beat is idle. This is also how you walk an array (fix the base, change the offset) and how code stays relocatable.

9 The Control Unit

Ways this is asked → “What does the control unit do?”, “Explain hardwired control”, “Explain microprogrammed control”, “Difference between hardwired and microprogrammed control” (very important).
What is the job of the control unit? 2–3 marks

Every clock, the control unit raises the exact control signals the current step needs — no more, no less. It reads three inputs — the IR (which instruction), a step counter (which beat, T1…T5), and the condition flags (Z, N, C, V) — and drives the control points: register load lines (MARin, MDRin…), bus enables (PCout…), the ALU function, and memory Read/Write.

It can be built two ways: hardwired or microprogrammed.

Explain hardwired control. 5 marks

In hardwired control the decision “which signals, which beat” is frozen into logic gates. Inside the box are three parts:

Hardwired = instruction decoder + step counter + control-signal generator (combinational logic).
  • The instruction decoder says which instruction (reads the opcode).
  • The step counter says which beat (T1…T5).
  • The control-signal generator (combinational logic) ANDs/ORs these into the signals.

Each control signal is just a Boolean equation — the OR of the steps that need it. For example:

Read = T1 + T4·LOAD

Fetch always reads on T1; a Load also reads its operand on T4. Wire up one such gate per signal and the control unit is built.

Trade-off: hardwired control is fast (signals appear in one gate delay, no memory to consult) but rigid (a new/changed instruction means redesigning the logic and re-fabricating the chip). RISC keeps its signals simple, so modern RISC CPUs are hardwired.
Explain microprogrammed control (in brief). 3–5 marks

In microprogrammed control the signals are not computed by gates — they are stored in a small on-chip memory (the control store) and looked up. Each step is one microinstruction: its bits are the control signals for that beat, plus a field saying where the next microinstruction is.

  • A μPC (micro-program counter) / CAR holds the address of the next microinstruction.
  • Each beat reads one word out of the control store; those bits drive the control points.
  • An address generator sequences through the words (increment, branch, opcode-map, End).

In one line: microprogrammed control keeps the signals as microcode in memory and reads one word per step. Change the design → just rewrite the microcode.

Differentiate hardwired and microprogrammed control. 5 marks · important

Both produce the same control signals; they differ only in where the decision lives — and everything else follows from that one line.

PropertyHardwiredMicroprogrammed
Decision lives infixed logic gatesa control store (memory)
Speedfaster — one gate delayslower — a memory read per step
Flexibilityrigid — must rewire to changeflexible — just rewrite microcode
Complex instruction setshard (huge logic)easy (just more microcode)
Design effort / cost to changehigh (redesign + re-fabricate)low (edit the control store)
Best fitRISC (simple, regular)CISC (rich, complex)
One sentence to memorise: hardwired control trades flexibility for speed; microprogrammed control trades speed for flexibility.
