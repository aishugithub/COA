1 The Five Functional Units & their Roles

Ways this is asked → “List / explain the functional units”, “With a neat block diagram…”, “Role of each unit”, “What is a processor?”
Explain the five functional units of a computer and the role of each. 5–10 marks

A computer is built from five functionally independent main units that exchange information over an interconnection network (bus):

UnitRole (what it does)
Input unitAccepts coded information from the user / other computers (keyboard, mouse, mic, camera) and converts it to binary for the processor.
Memory unitStores the programs (lists of instructions) and the data. Split into primary/main memory, cache and secondary storage.
ALU (Arithmetic & Logic Unit)Performs all arithmetic (add, subtract…) and logic (AND, OR, compare) operations on operands held in registers.
Output unitSends processed results back to the outside world (printer, display).
Control unitThe “nerve centre” — coordinates every other unit by issuing timing and control signals.
Key definition (worth a mark): the ALU + Control unit + registers together are called the Processor (CPU). Input and Output are often together called I/O units.

One-liner to memorise: Input → Memory → ALU (via registers) → Output, all orchestrated by Control.

What are the functions of the Control unit? Why do we say the Control unit “controls” all the other units? 5 marks

The Control unit reads the instruction sitting in the IR, decodes it, and then drives every other unit at exactly the right instant. It “controls” the whole machine because it is the only unit that issues two kinds of signal that tell every other unit when and what to do:

SignalAnswers…Meaning
① Clock (timing) signals — the clock pulseWHEN?The steady beat. Every unit acts on the tick, then waits for the next one.
② Control signalsWHAT?“Latch this register”, “put that value on the bus”, “tell the ALU to add”.
Answer in one line: the Control unit controls all other units because it supplies the clock (timing) signals and the control signals — WHEN + WHAT — that every other unit obeys. Its circuitry is physically distributed throughout the machine, not sitting in one spot.

Explain the Memory unit / the three kinds of memory in brief. 3–5 marks

The Memory unit stores the programs and the data. It has three tiers:

  • Primary (main) memory — fast semiconductor RAM, used while a program is running; any location is reached in a fixed time (random access). Data is handled in words, each with a distinct address.
  • Cache — a small, even-faster RAM close to the processor holding the currently-used instructions/data, to speed execution.
  • Secondary storage — cheap, large, permanent (keeps data with power off): magnetic disk, optical disk, flash memory.

Remember the trade-off: as you go cache → main → secondary, it gets bigger and cheaper but slower.

2 Registers — the Special & General Purpose Registers

Ways this is asked → “What are registers?”, “Explain PC and IR”, “Special- vs general-purpose registers”, “What is a register file?”
A program in memory is just numbers. How does the processor actually run it — where do registers come in? 3 marks

By the stored-program concept, the program (a list of instructions) and its data both sit in memory as numbers. The processor fetches instructions one by one and executes them. To do this at high speed it keeps a handful of small, very fast storage cells inside itself called registers — some with a fixed special job, some for holding operands. Registers are faster than cache, which is faster than main memory.

Explain the special-purpose registers (PC, IR, MAR, MDR). 4–5 marks
RegisterFull nameHolds…
PCProgram Counterthe memory address of the NEXT instruction to be fetched — it “points” to the next instruction.
IRInstruction Registerthe instruction CURRENTLY being executed (its bits drive the control signals).
MARMemory Address Registerthe address of the memory location to be accessed.
MDRMemory Data Registerthe data being written to, or just read from, memory.
MAR + MDR are the processor’s gateway to memory. These four one-liners are a guaranteed 4 marks — write them exactly as above.
What are general-purpose registers and the register file? 3 marks

General-purpose registers (GPRs), written R0, R1, … R(n−1), are fast storage cells that hold the operands brought in from memory for immediate processing (and the results). Unlike PC/IR/MAR/MDR they have no fixed special job — the program may use any of them for any value.

The whole set of general-purpose registers, addressed by number, is called the register file. In a RISC machine the ALU takes its inputs from, and writes its result back to, the register file — which is why an instruction can finish in about one clock cycle.

Distinguish special-purpose registers from general-purpose registers. 2 marks

Special-purpose registers (PC, IR, MAR, MDR) each have one fixed role the hardware assigns. General-purpose registers (R0…Rn−1, the register file) are freely usable by the program to hold any operand or result.

3 Bus Structures — connecting the Functional Units

Ways this is asked → “What is a bus?”, “Single-bus vs multiple-bus”, “Advantages/disadvantages of single bus”, “Explain address/data/control bus”.
What is a bus? 2 marks

A bus is a shared set of wires that transfers data and control information between the functional units (processor, memory, I/O). Because it is shared, only one source may drive it at a time. It is built using multiplexers or tri-state (three-state) buffers so that many units can share the one physical path without interfering.

Explain single-bus organisation: its advantages, its disadvantage, and why we move to a dual / multiple-bus structure. 5 marks

In a single-bus organisation all units connect to one common bus, which is the sole path for every transfer.

Single bus — one shared highway, taken in turns.
✔ Advantages✘ Disadvantage
Low cost · simple to design · easy to add a new device (just tap the bus).Only one transfer at a time — the single bus becomes the bottleneck.

Why move to dual / multiple buses? To remove that bottleneck. With two buses (one for instructions, one for data) a fetch and a data move can happen at the same time. With multiple buses each bus runs at the speed of what it joins (a fast processor–cache bus, the system bus to memory, a slower expansion bus for peripherals). The gain is more parallelism; the cost is more wiring / complexity.

Every bus is really three groups of lines — explain the address bus, data bus and control bus, and state what travels on each during a memory READ and a memory WRITE. 5–10 marks

Any bus is actually three groups of lines, each answering a different question:

The three line-groups: address (where), data (what), control (when / which way).
BusCarriesDirection
Address bus — WHERE?the address to be accessed; k lines → 2k locations.usually one-way (processor → memory)
Data bus — WHAT?the data / instruction word.both ways (bidirectional)
Control bus — WHEN / which way?Read/Write line, timing and status signals.as needed
What goes where during READ vs WRITE (examiners love this):
  • Memory READ: processor puts the address on the address bus and asserts Read on the control bus; memory returns the word on the data bus (memory → processor). Original memory contents stay unchanged.
  • Memory WRITE: processor puts the address on the address bus, the data on the data bus, and asserts Write on the control bus; memory overwrites that location.
Notice: on both, the address bus is one-way; only the direction of the data bus flips, decided by the control bus (Read vs Write).

Differentiate single-bus and multiple-bus structures in one line. 2 marks

Single = one shared path — cheap, simple, but one transfer at a time. Multiple = several parallel paths — faster (overlapping transfers) but costlier and more wiring.

4 How Memory is Organised

Ways this is asked → “Byte addressability”, “Aligned vs unaligned words”, “Big-endian vs little-endian (with example)”, “k-bit address → how many locations?”.
What is byte-addressability? Define bit, byte and word, and give the addresses of successive words. 4 marks
  • Bit — the smallest unit of information, a 0 or a 1.
  • Byte — a group of 8 bits.
  • Word — the n-bit unit the processor handles in one operation (word length is typically 16 / 32 / 64 bits).

Byte-addressable means every 8-bit byte has its own distinct address (0, 1, 2, 3, …). A 32-bit word is any four consecutive bytes, so successive words sit at addresses 0, 4, 8, 12 … — four bytes apart.

Address-space formula: a k-bit address can name 2k locations (e.g. 32-bit address → 232 = 4G locations).
What is word alignment? When is a word aligned or not aligned? 3 marks

A word is aligned if it begins at a byte address that is a multiple of the number of bytes in a word. For a 32-bit (4-byte) word, aligned addresses are 0, 4, 8, 12 …

So a word starting at address 8 is aligned (8 is a multiple of 4), but one starting at address 6 is NOT aligned. Unaligned access still works but is less efficient / slower for the processor.

Explain big-endian and little-endian byte ordering with an example. 5 marks

Endianness is the order in which the bytes of one word are placed into successive byte addresses:

  • Big-endian — the most-significant byte (MSB) goes to the lowest address.
  • Little-endian — the least-significant byte (LSB) goes to the lowest address.
Same word, same address 0 — only the byte order differs. Intel x86 is little-endian.
Exam tip: the word address (0, 4, 8…) is the same in both systems — only the order of the bytes inside the word changes. Intel x86 = little-endian.

5 Reading & Writing a Word from Memory

Ways this is asked → “Explain memory Read and Write operations”, “Describe a Read/Write cycle using MAR and MDR”.

⚠ Important — this question spans Unit 1 and Unit 2. Full answer is in Unit 2.

In Unit 1 the Read/Write story is told only at the level of the three buses — which is already covered in Section 3 above:

  • Read = address on the address bus + Read on the control bus → word returns on the data bus (memory unchanged).
  • Write = address on the address bus + data on the data bus + Write on the control bus → location is overwritten.

In Unit 2 we will answer the same question at full depth using Register Transfer Language (RTL) and the MAR / MDR registers — e.g. a Read is MAR ← [PC]; Read; MDR ← [M[MAR]] and a Write is M[MAR] ← [MDR]; Write. Because the RTL description belongs to the processing-unit topic, we will take the complete Read/Write cycle (Unit 1 bus view + Unit 2 RTL view) together in Unit 2.

6 Instructions — Opcode, Operands & Classification

Ways this is asked → “Parts of an instruction”, “Classify instructions by function / operand count / format”, “Zero-, one-, two-, three-address instructions with example”.
What are the parts of a machine instruction? (opcode + operand) 2–3 marks

Every instruction has two parts:

  • Opcode (operation code) — what to do (e.g. Load, Add, Store).
  • Operand(s) — what to do it on: a register, a memory address, or a constant (an operand may also be implied and not written).

Examples: Load R2, A → opcode Load, destination R2, source address A.   Add R4, R2, R3 → three operands: destination R4, sources R2 and R3.

The assembler translates these symbolic mnemonics into the binary object program the hardware runs.

Differentiate RISC and CISC. 5 marks

RISC (Reduced Instruction Set Computer) — a small, simple set; each instruction fits in one word and runs in about one clock cycle; load/store architecture (only Load/Store touch memory).

CISC (Complex Instruction Set Computer) — a large, rich set; instructions vary in length and can span multiple words; arithmetic may act directly on memory operands.

One-line trade-off: CISC does more per instruction; RISC does less per instruction but runs them faster and more predictably.

7 Addressing Modes

Ways this is asked → “Explain addressing modes with examples”, “Give the effective address for each mode”, “Which mode is best for arrays?”.
Explain the different addressing modes with an example and the effective address (EA) of each. 10 marks

An addressing mode is the rule that tells the processor where to find the operand. The effective address (EA) is the actual address finally used.

ModeNotation / ExampleEffective address / meaning
ImmediateMove R2, #5operand is inside the instruction → R2 ← 5; no memory access.
RegisterAdd R4, R2, R3operand is in a register; EA is the register itself — the fastest mode.
Absolute / DirectLoad R2, Ainstruction holds the address → EA = A; R2 ← [A]. One memory access.
IndirectLoad R2, (R5)the register/location holds the address of the address → EA = [R5]; a pointer. R2 ← [[R5]].
IndexLoad R2, 20(R5)EA = 20 + [R5] — a base register plus an offset. Made for arrays.
RelativeBranch>0 LOOPindex mode with the PC as base → EA = X + [PC]; used to jump to instructions (position-independent code).
Autoincrement(R5)+use [R5] as the address, then R5 ← R5 + 1. Step forward through an array.
Autodecrement−(R5)R5 ← R5 − 1 first, then use [R5]. Natural for a stack (push/pop).
Worked example for Index: if R5 = 1000, then 20(R5) reaches address 1020. Fix the base at the array start, change the offset to step to any element.

Fastest → slowest to reach the operand: Immediate / Register (no memory) → Absolute (1 access) → Indirect (2 accesses).

Why keep operands in registers (register mode)? 2 marks

A register read is a tiny fraction of the time of a memory read. RISC machines keep operands in registers precisely so that an arithmetic instruction can finish in about one clock cycle, with no memory access.

8 Instruction Sequencing

Ways this is asked → “Straight-line vs branching”, “Unconditional vs conditional branch”, “How does a conditional branch decide?”, “Branch target vs offset”.
What is straight-line sequencing? 3 marks

By default the processor executes instructions in order of increasing addresses. After each fetch the PC is auto-incremented by the word length (e.g. PC ← PC + 4 for 4-byte words), so it points to the next instruction. This default flow is called straight-line sequencing.

Each fetch adds the word length to the PC, so instructions run in address order.

There are only two kinds of sequencing: straight-line (PC just steps on) and branching (a new address is loaded into the PC).

What is an unconditional branch (jump)? 3 marks

An unconditional branch (a jump) loads a fixed target address into the PC every time, with no test — e.g. Branch 100 does PC ← 100 always. It is used to loop back to the top of a block or to skip ahead.

It is the same kind of PC move as straight-line — both just load an address — the only difference is straight-line loads PC+4 while the jump loads a written target. On its own a jump-back loops forever; to decide whether to jump you need a conditional branch.

What is a conditional branch, and how does it decide whether to jump? 5 marks

A conditional branch jumps only if a tested condition is true — e.g. Branch>0 116.

How it knows: the preceding instruction (a Compare or arithmetic op) stores its outcome in the processor’s condition-code flags — a small status register recording was the result zero? negative? …. The conditional branch simply reads those flags. That is why a conditional branch always sits right after an instruction that sets the flags.

Then, exactly like a jump, it either loads the new address into the PC (taken) or lets the PC step on to the next instruction (not taken).

Worked example — put the larger of A, B into MAX:
Load R1, A · Compare R1, B · Branch>0 116 · Load R1, B · Store R1, MAX
If A=5, B=3 → 5>3 is YES → branch taken, skip the reload → MAX = 5.
If A=3, B=5 → 3>5 is NO → not taken, PC steps on, R1 reloaded with B → MAX = 5.
Differentiate branch target and branch offset. 2 marks

Branch target = the destination address the processor jumps to. Branch offset = the distance from the current PC to that target (offset = target − PC of next instruction). Storing the small offset makes the code position-independent: EA = PC + offset.
